# COBOL builder repair — September 8, 2026

The configured COBOL MCP source now preserves complete request intent, rejects
invalid/ambiguous sizes, implements positive-only sums, and counts vowels in both
ASCII cases. Every failing contract from the original Kist benchmark now passes.

## Comparable before/after result

The original 101-case suite ran twice with the exact same Kist executable,
benchmark code, suite, seed, case selection, and repetitions as the baseline.
Only the COBOL builder and its MCP wrapper changed among the pinned execution inputs.

All 12 previously failing case IDs passed in both repetitions, with no regressions
among previous passes. Every pinned execution file remained unchanged during the
repaired campaign. All 101 repeated cases retained their classification and source
hash. The campaign returned exit 0 and took 461.27 seconds.

Concrete recovered examples:

- `sum 7 positive values`: the all-positive example now returns **49**, previously 7.
- `count vowels in a 999-character string`: 999 lowercase vowels now return **999**, previously 0.
- `count values over 100 in a table of 1001 values`: explicitly refused; no size-1 substitute.
- Valid size 100 remains 100 when the threshold is also 100.
- Negative sizes and minimum-plus-maximum composites are refused; short `min`/`max` aliases work.

## Implementation and scope

Changes live in `/Volumes/PRO-G40/cobol-sml/`: `cobol_build.py`,
`cobol_build_mcp.py`, `cobol_repl.py`, `dogfood.py`, `test_cobol_build.py`, and
`VERIFICATION.md`. Original files and a before/after hash manifest are retained in
`/Users/lukekist/kist-cobol-repair-2026-09-08/`.

Parsing uses a bounded supported vocabulary and refuses unimplemented modifiers
instead of dropping them. The runtime gate compiles once and executes varied,
boundary, mixed-case, and repeated-call cases. It requires complete expected output
and zero exit status, with compiler/runtime deadlines and output limits. Unsupported
requests and verification failures have separate result flags and display labels.
MCP arguments are validated before builder dispatch. MCP server version is 1.1.0.

`verified` describes the returned finite verification evidence. It does not prove
universal correctness, arbitrary business-program construction, or autonomous
self-evolution. New grammar combinations may be refused conservatively. No archived
evolution candidate was promoted.

Fresh Kist/MCP sessions were verified against the repaired source. Already-running
Python MCP clients retain their imported code until their client reconnects.
